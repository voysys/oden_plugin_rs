1//! Oden Rust Plugin Wrapper
2//!
3//! `oden_plugin_rs` is a Rust wrapper for the Oden C plugin API, enabling users
4//! to write plugins in Rust that calls the C API.
5//!
6//! # Oden Plugin API Overview
7//! Oden offers an API for creating plugins. Several functions are called by Oden
8//! during the lifetime of a plugin. These functions, together with some meta data,
9//! are registered using a macro.
10//! Examples of what plugins can be used for:
11//! - Visualize sensor data
12//! - Support control surfaces
13//! - Data analysis
14//! - Autonomous functions (based on sensor data)
15//! - Create custom 2D or 3D GUI:s
16//! - Custom visualizations
17//!
18//! # DLL and .so
19//! Plugins compile to `.dll` files on Windows and `.so` files on Linux. Oden will find
20//! plugins by looking for `.dll`/`.so` files in the Oden installation directory
21//! and in the project specific plugin directory.
22//!
23//! > **Note**: The UUID that identifies a plugin needs to be unique for each
24//! > plugin. Generators for UUIDs can be found freely online.
25//!
26//! # Plugin Structure
27//!
28//! Filename: hello_world.rs
29//! ```
30//! use oden_plugin_rs::{
31//!     math::{Vec3, Vec4},
32//!     register_plugin, GuiParams, InitParams, OdenPlugin, ShutdownParams, UpdateParams,
33//! };
34//!
35//! struct State {
36//!     _dummy: bool,
37//! }
38//!
39//! impl OdenPlugin for State {
40//!     fn init(_api: &InitParams) -> Self {
41//!         State { _dummy: false }
42//!     }
43//!
44//!     fn shutdown(self, api: &ShutdownParams) {}
45//!
46//!     fn update(&mut self, api: &UpdateParams) {
47//!         api.im_draw_add_text(
48//!             "Hello World!",
49//!             Vec3::xyz(-1.0, 0.0, -2.0),
50//!             Vec3::xyz(0.0, 0.3, 0.0),
51//!             Vec3::xyz(1.0, 0.0, 0.0),
52//!             Vec4::rgba(0.8, 0.8, 0.8, 1.0),
53//!             0,
54//!         );
55//!     }
56//!
57//!     fn gui(&mut self, api: &GuiParams) {
58//!         api.label("Hello World!");
59//!     }
60//! }
61//!
62//!
63//! ```
64//!
65//! ## Init
66//!
67//! [`OdenPlugin::init`] is called when the plugin is initialized.
68//! This is an appropriate place to create data for storing state and/or initializing threads.
69//!
70//! ## Update and GUI
71//! The Oden Application runs a loop in which it calls [`OdenPlugin::update`] on all entities and then allows them
72//! to draw a GUI, and then does the drawing to screen. The rate of this loop is
73//! displayed in the top right corner (in Hz / fps).
74//!
75//! [`OdenPlugin::update`] is called once per Oden iteration for all non-hidden entities. This is the
76//! proper place to do drawing or light recurring compute tasks.
77//!
78//! > **Note**: For heavier compute-tasks a separate thread should be spawned from [`OdenPlugin::init`].
79//!
80//! The [`OdenPlugin::gui`] function is called if the sidebar GUI of a plugin is visible. This is a
81//! good place to inspect and alter variables and show debug information in an easy
82//! way.
83//!
84//! ## Draw
85//!
86//! The function [`OdenPlugin::draw`] allows for using raw OpenGL commands.
87//!
88//! > **Note**: This is very complex and is not covered in the example plugin.
89//!
90//! ## Shutdown
91//! The [`OdenPlugin::shutdown`] call comes when the plugin is closing down. Data allocated during
92//! [`OdenPlugin::init`] must be freed here.
93//!
94//! [`OdenPlugin::update`]: crate::OdenPlugin::update()
95//! [`OdenPlugin::init`]: crate::OdenPlugin::init()
96//! [`OdenPlugin::gui`]: crate::OdenPlugin::gui()
97//! [`OdenPlugin::shutdown`]: crate::OdenPlugin::shutdown()
98//! [`OdenPlugin::draw`]: crate::OdenPlugin::draw()
99//!
100//! ## API Reference for OdenPlugin trait
101//! [`InitParams`] contains the functions implemented for the init function. \
102//! [`UpdateParams`] contains the functions implemented for the update function. \
103//! [`GuiParams`] contains the functions implemented for the gui function. \
104//! [`DrawParams`] contains the functions implemented for the draw function. \
105//!
106//! ## Functions In-parameters
107//! There are some global functions available in the plugin API (accessed via the
108//! `oden` global variable). The global API functions are safe to call from all
109//! functions and they are also safe to call from other threads. All other API calls
110//! are available on parameters passed into each of the functions that get called
111//! from Oden (init, update, gui, shutdown, draw). It is safe to call all functions available in
112//! the `api` parameter given in each function call. It is not safe to call functions
113//! passed to one of the functions in any of the other functions, or to call them from
114//! another thread.
115//!
116//! ## Data Management
117//! All data needs to be managed and created in a way that allows for multiple
118//! instances of each plugin to coexist.
119//!
120//! > **Important**: Do not use global or static variables. It will
121//! > prevent multiple plugin instances and is not thread safe.
122//!
123//! ## Control and Names for Entities
124//! Many functions in the plugin API use names to identify entities. When entities
125//! are added to the scene graph in Oden they are default created without names.
126//! To make these functions work, it is important to give them names.
127//!
128//! With all `entity` related functions, it is also possible to concatenate _@_
129//! and a scene name to `entity` in order to get/set an entity in a specific scene, e.g.
130//! _Remote Streamer@Input_ if the entity is called _Remote Streamer_ and the scene _Input_.
131//! This is useful if the plugin is running in a different scene to the entity that you want.
132//!
133//! > **Note**: Entities are named using the “Name” option available when
134//! > selecting the entity in the scene graph.
135//!
136//! # Immediate Mode: GUI and ImDraw
137//! Oden uses a paradigm called “immediate mode” for GUI and drawing functions
138//! (ImDraw). An immediate mode GUI is different from a traditional retained
139//! mode GUI. In retained mode GUIs a widget is registered and callbacks or state
140//! variables are set up that signals when things happen in the GUI. In contrast,
141//! an immediate mode GUI is drawn in each frame and the actions happen in the
142//! same code that draws the gui.
143//!
144//! ## Dear ImGui
145//! The GUI framework that Oden uses for the sidebar GUI is called “Dear ImGui”.
146//! Documentation is available for Dear ImGui online.
147//!
148//! ## Label Uniqueness
149//! Dear ImGui uses canonical label strings to identify widgets. These need to be
150//! unique.
151//!
152//! # Raw Recording
153//!
154//! A plugin may be used to provide support for something that provides or accepts
155//! real time data. Writing a plugin allows visualizing sensor data in Oden,
156//! and at the same time e.g. show video from cameras.
157//! Oden provides a raw recording functionality to save exact
158//! data coming into Oden for later playback.
159//!
160//! Raw recording is useful in many scenarios, e.g. algorithm development.
161//! To support the same kind of functionality as Oden
162//! support for raw recording, there are functions provide during update and also a
163//! separate function call available for playback.
164//!
165//! During update, data can be sent to raw recording from the plugin. During
166//! playback the recordingPlayback function will be called and will be passed data
167//! that was sent from update when the system was live.
168//!
169//! # Hot Reloading
170//!
171//! During development it is important to have a quick iteration time from code change to running application. During the development of a plugin Oden
172//! therefore offers hot reloading, so if the plugin `.dll`/`.so` is updated while Oden is
173//! running then the plugin will be reloaded with the new code.
174//!
175//! Hot reloading resets the data state of the plugin (shutdown is called on the old
176//! plugin and init is called on the new). In some cases this is not desired, and for
177//! these cases Oden offers data migration functionality.
178//!
179//! > **Important Note**: Hot reloading is highly discouraged for production use and
180//! > should only be used in development!
