Host side of the message bus.

The host publishes a factory record — the address of a BusHostVTable living in the host executable — under HOST_FACTORY_KEY in the plugin data-sharing store, before any plugin runs. BusOwner::open allocates every bus through that factory, so both the bus vtable code and the BusState reside in the host binary and stay valid across any plugin DLL/SO unload.

Oden does this by linking this crate into the host (via oden_rs) and calling host_factory_record there; the record’s function pointers therefore point into the host’s own copy of imp, not into any plugin.

Constants§

HOST_FACTORY_KEY
Data-sharing key under which the host publishes its bus factory record.
HOST_FACTORY_RECORD_SIZE
Size in bytes of the on-wire factory record. 8 (magic) + 1 (pointer width) + 7 (reserved) + 8 (vtable) + 8 (reserved) = 32, mirroring the bus discovery record.

Functions§

host_factory_record
Serialize the factory record for this build’s BusHostVTable. The record embeds pointers into whatever binary this crate is linked into, so it must only be published by a module that is never unloaded — in practice the host executable.
